## Deployment recovery

When a saved market publication reaches GitHub but its Pages deployment is missing, Collector waits for an existing build or submits one recorded recovery request. GitHub main must still match the saved publication, the fixed Pages project must be enabled, and live dataset hashes must match before report delivery proceeds. A lost response or restart never authorizes another recovery request. The daily report identity stays unchanged, and post-report refresh never resends it.

The recent-deployment lookup supports projects with more than 100 records. It does not assert global absence: a delayed native trigger can coexist with the one Collector recovery build. This release preserves the durable admission claim and includes an observed fail/pass/fail/pass regression for long histories and uncertain responses across restart.

After installation, the owner saves a private Cloudflare API token with Account / Cloudflare Pages / Edit permission limited to the Atlas account through **Market ingestion → Cloudflare Pages recovery token**. Saving validates project access and stores the token privately. It does not collect, publish or send a report. See [setup instructions](https://github.com/drumfeet/atlas-almanac-collector/blob/v0.5.7/docs/DEPLOYMENT-RECOVERY.md).
